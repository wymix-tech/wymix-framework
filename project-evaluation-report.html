TravelSky Dev Framework 项目评估报告

GroupId: com.travelsky.base | Version: 3.0.0-SNAPSHOT | Spring Boot 3.5.8 + Java 17

一、项目概览

本项目是航信(TravelSky)内部的企业级 Java 快速开发框架，代号 APD。基于 Spring Boot 3.5.8 和 Java 17 构建，采用 Maven 多模块架构，共包含 16 个子模块，覆盖从基础工具到 Web 层、安全认证、缓存、监控、服务发现等企业级开发全链路能力。项目附带一个 Groovy 代码生成器(code-generator)和一个示例应用(sample)。

四、核心特性详解

1. 双 ORM 引擎支持

同时提供 JPA (Hibernate) 和 MyBatis-Plus 两套 Repository 实现，共享 dev_repository 抽象层。业务可根据需求选择 ORM，甚至同时使用（data_migration 模块即同时依赖两者）。

2. 查询 DSL (DevQueryVO)

自研类 Lisp 嵌套括号表达式查询语言，前端通过 filter 字符串传递查询条件，后端自动解析为 SQL。支持 15 种操作符（eq/ne/gt/ge/lt/le/like/in/notIn/between/isNull/isNotNull 等），支持 AND/OR 逻辑组合和嵌套分组。

3. 数据权限 (@DataPermission)

基于 AOP + MyBatis-Plus SQL 注入器实现行级数据权限控制。通过 @DataPermission 注解声明式配置，可指定 statementId 和自定义 PermissionSqlInjector 实现灵活的权限过滤。

4. 数据变更日志 (DataChangeLog)

通过 @DataChangeLog 注解标记实体，自动记录 INSERT/MODIFY/REMOVE 操作。支持 SQL 解析 (SqlParseHelper)，发布 DataChangeLogEvent 事件供其他模块消费。

5. JWT 认证体系

完整的 Spring Security + JWT 无状态认证方案。支持令牌黑名单（登出失效）、配置密码加密（ENC()）、BCrypt 密码编码、自定义安全配置扩展点 (SecurityCustomizer)、随机密钥生成等。

6. 去中心化服务发现

基于 JmDNS 实现 mDNS 协议的服务广播与发现，无需部署 Eureka/Nacos 等外部注册中心。配合 DynamicServiceInstanceSupplier 和 DynamicInstanceManager 实现 Feign 调用的动态实例管理。

7. 多级缓存策略

Hazelcast 分布式缓存（支持 TCP/IP 单机/集群模式、LRU/LFU 淘汰策略、多命名空间 TTL 配置）+ Caffeine 本地缓存（可配置初始容量/最大容量/权重/写入后过期/访问后过期/刷新），通过条件注解按需启用。

8. 线程池运行时管理

ThreadPoolRegistry 注册中心 + Web 控制器 (ThreadPoolWatchController/ThreadPoolOperateController)，支持运行时查看和调整线程池参数。使用 TransmittableThreadLocal 实现线程间上下文透传。

9. 请求全链路追踪

Log4j2 ThreadContext + 自定义 customTraceId，通过 Filter 在请求入口生成 TraceId，TaskDecorator 将 TraceId 透传到异步线程，实现全链路日志关联。

10. Groovy 代码生成器

独立 Groovy 项目，连接 MySQL 数据库读取表结构，交互式生成 Entity/VO/Dao/Service/Controller 全栈 CRUD 代码，继承框架基类。

五、框架优点

  1. 模块化设计清晰 — 16 个模块按职责分层（基础/核心/数据/基础设施/应用），依赖方向自上而下，模块边界明确，可按需引入。
  2. 技术栈现代 — Spring Boot 3.5.x + Java 17，Jakarta EE 命名空间，紧跟主流生态。Log4j2 替代 Logback、Undertow 替代 Tomcat 的选择体现了性能考量。
  3. 企业级功能完备 — 认证授权、分布式/本地缓存、监控告警、动态数据源、数据权限、数据变更日志、请求追踪、防重复提交等一应俱全，开箱即用。
  4. 双 ORM 灵活性 — 同时支持 JPA 和 MyBatis-Plus，共享抽象层，业务可按场景选择甚至混用。
  5. 自研查询 DSL 有创新 — 类 Lisp 嵌套括号表达式，前端无需了解后端 SQL 即可构造复杂查询，且提供了 AI 提示词模板，对低代码/AI 场景友好。
  6. 去中心化发现避免外部依赖 — JmDNS 方案无需部署 Eureka/Nacos，降低运维成本，适合小规模内部微服务场景。
  7. 线程池可观测可控 — 运行时通过 Web 接口监控和调整线程池参数，配合 TTL 上下文透传，生产实用性强。
  8. 测试基础设施完善 — Testcontainers 封装了 Oracle/PgSQL/Kafka/Redis 容器，DBUnit 支持 Excel 数据集，集成测试门槛低。
  9. 代码生成器提效 — Groovy 脚本一键生成全栈 CRUD 代码，继承框架基类，减少样板代码。
  10. CI-friendly 版本管理 — 使用 flatten-maven-plugin + ${revision} 统一版本号，适配 CI/CD 流水线。
  11. 安全细节到位 — 配置密码 ENC() 加密、JWT 令牌黑名单、BCrypt 密码编码、无状态会话等安全实践。

六、框架缺点与不足

  1. 部分模块不完整 — AI 模块仅有空壳 pom.xml 无任何源代码；DataMigration 模块的 dataMigration() 方法体为空，仅搭建了事件监听骨架；RepeatRequestAspect 在 WebConfiguration 中被注释掉未启用。
  2. 文档严重不足 — README 仅列出模块名和启动代码片段，缺少架构说明、配置指南、API 文档。FILTER_USAGE_GUIDE.md 是唯一的详细文档（查询 DSL 用法），其他模块无使用说明。
  3. Spring Cloud 版本不匹配 — 框架基于 Spring Boot 3.5.8，但 Spring Cloud 依赖版本为 3.1.3（对应 Spring Boot 3.x 早期版本），存在版本兼容风险。应升级至 2025.x (Spring Cloud)。
  4. 自动配置方式不统一 — 大部分模块使用 Spring Boot 3 的新式 AutoConfiguration.imports，但 security 和 dynamic_datasource 仍使用旧式 spring.factories 注册 EnvironmentPostProcessor，风格不一致。
  5. CachingConfigurerSupport 已废弃 — CacheManagerConfiguration 继承的 CachingConfigurerSupport 在 Spring Boot 3.x 中已标记为 @Deprecated，应改为实现 CachingConfigurer 接口。
  6. 代码生成器安全隐患 — Groovy 脚本中硬编码了数据库连接地址、用户名和明文密码 (Adt@2025!)，且 groupId 为 org.wy（个人包名），未纳入父项目统一管理。
  7. 去中心化发现可扩展性存疑 — JmDNS 基于 mDNS 多播协议，在跨网段/云环境/容器网络中多播通常被禁用，不适合大规模或跨网络部署。缺少对 Docker/K8s 环境的适配方案。
  8. Hazelcast 版本偏旧 — 5.2.5 发布于 2023 年，当前 5.x 已有更新版本，可能存在已修复的安全漏洞和性能问题。
  9. 缺少单元测试 — 框架模块自身没有任何单元测试代码，dev_test 模块仅提供测试基础设施（Testcontainers 封装），但框架核心逻辑未被测试覆盖。
  10. SecurityConfiguration 设计偏抽象 — CustomSecurityConfiguration 为抽象类，用户必须自行实现 SecurityFilterChain 或继承配置，但缺少文档说明如何扩展，上手门槛较高。
  11. DataChangeLog 注解重复定义 — dev_repository、dev_jpa_repository、dev_mybatis_repository 三个模块各自定义了 DataChangeLog/EnableDataChangeLog 注解，命名空间和包路径不同，容易混淆。
  12. 缺少条件装配保护 — 部分自动配置类（如 MyBatisConfiguration、MonitorConfiguration）缺少 @ConditionalOnProperty 开关，引入模块即强制生效，无法按需关闭。

七、改进建议

  1. 补全 AI 模块 — 明确 AI 模块定位（LLM 调用 / RAG / Agent），引入 Spring AI 或直接对接 API，填充源代码。
  2. 完成 DataMigration 实现 — 实现 dataMigration() 方法体，支持跨数据源的增量/全量数据迁移，可参考 Flyway/Liquibase 的变更日志模式。
  3. 启用 RepeatRequestAspect — 取消 WebConfiguration 中的注释，配合 Redis/Caffeine 实现分布式防重复提交。
  4. 对齐 Spring Cloud 版本 — 升级至 Spring Cloud 2025.x，与 Spring Boot 3.5.8 保持兼容，修复 OpenFeign + LoadBalancer 的版本不匹配问题。
  5. 统一自动配置方式 — 将 security 和 dynamic_datasource 的 EnvironmentPostProcessor 注册迁移至 spring/ 的标准位置或改用 @AutoConfiguration + @Import 机制。
  6. 替换废弃 API — 将 CachingConfigurerSupport 替换为实现 CachingConfigurer 接口，消除废弃警告。
  7. 编写文档 — 为每个模块编写 README，包含功能说明、配置项、使用示例。补充架构设计文档和快速上手指南。
  8. 代码生成器安全化 — 移除硬编码凭据，改为环境变量/配置文件读取；纳入父项目 Maven 管理，统一 groupId。
  9. 统一 DataChangeLog 注解 — 在 dev_repository 中统一定义注解，JPA/MyBatis 模块共享，避免重复定义和包路径混淆。
  10. 增加条件装配 — 为所有自动配置类添加 @ConditionalOnProperty 前缀开关，实现真正的按需加载。
  11. 补充单元测试 — 为框架核心逻辑（BootLoader、查询 DSL 解析器、数据权限 AOP、JWT 工具类等）编写单元测试。
  12. 升级依赖版本 — Hazelcast 升级至最新 5.x，定期检查并更新所有第三方依赖。
  13. K8s 适配方案 — 为去中心化发现提供 K8s Headless Service 适配模式，或在容器环境中降级为配置式注册。

八、总体评价

该项目作为一个企业内部开发框架，功能覆盖面广，模块化设计合理，技术选型现代。自研的查询 DSL、数据权限 AOP、去中心化服务发现等特性展现了较强的工程创新能力。双 ORM 支持和 Groovy 代码生成器提升了开发效率。

主要短板在于：文档缺失导致上手门槛高，部分模块未完成影响整体完整性，版本对齐和废弃 API问题需要及时处理。建议优先补充文档、完成骨架模块、对齐依赖版本，然后逐步增加测试覆盖。

总体评分：7.5 / 10 — 功能丰富、设计有亮点，但完成度和文档有待提升。
